**Audit date:** 2026-09-30  
**Recovery branch:** `agent/restore-docs-center-0.8-20260930`  
**Source backup:** `docs-preview.earthcoop.ir.zip` supplied by the owner before recovery work

## Purpose

This audit freezes the exact pre-auto-deploy Docs Center UI/runtime baseline before any recovery or integration changes. The goal is to preserve the approved 0.8 UI/UX and reconnect it to the current governed repository content and multilingual metadata without re-designing the product or redoing prior content work.

## Non-negotiable corrections

1. The repository's `ar/` tree is **not an Arabic translation corpus**. It contains Persian content placed under the Mintlify Arabic/RTL compatibility locale because the legacy authoring/runtime stack did not support Persian directly. It must never be presented as Arabic in the independent Docs Center.
2. The independent runtime may expose Arabic only when a real Arabic rendition exists and is explicitly registered as such in governed metadata.
3. Existing English material must be classified by evidence and registry state; physical presence of an English file does not automatically make it authoritative/current.
4. The Persian corpus remains the canonical/source language for foundational legal documents unless governed metadata says otherwise.

## Current-repository content work that must be preserved

Recovery must not roll back the current repository's later work. The recovered 0.8 UI is the presentation/runtime baseline only. Current repository authority remains with the governed source and metadata layers, including:

- `document-registry.json` public-baseline and translation/editorial status model;
- `docs-manifest.json` logical document identities and rendition metadata;
- `REGISTRY_MODEL.md` status-semantics rules;
- terminology validation;
- translation freshness validation;
- evidence-backed product-guide corrections;
- registered release snapshots and current governed Persian source files.

The recovery implementation must adapt the 0.8 data adapters/generators to consume these current sources instead of restoring stale 0.8 document data as authority.

## Language contract for recovery

For the independent Docs Center:

- `fa`: real Persian UI/content and canonical foundational source language;
- `en`: only real English content that exists and is permitted by governed metadata;
- `ar`: **unavailable until real Arabic translations are created and registered**;
- legacy Mintlify `ar/` paths containing Persian are compatibility artifacts and must not be treated as Arabic renditions.

This contract supersedes any inference based solely on directory names.

## Recovery sequence

1. Preserve this fingerprinted 0.8 baseline unchanged as the reference.
2. Add regression tests that fail if the independent runtime no longer carries the established 0.8 layout/modules/behaviors.
3. Replace the temporary new `site/` shell with the 0.8 runtime/source baseline.
4. Build adapters/generators from current `docs-manifest.json`, `document-registry.json`, current source files and governed English material into the 0.8 runtime model.
5. Explicitly exclude legacy Persian-under-`ar/` files from Arabic availability.
6. Keep the already-working CI/build/artifact/strict-FTPS/live-SHA deployment chain.
7. Run visual/functional UAT against the recovered 0.8 design before any production cutover.

## Scope boundary

This recovery does **not** authorize rewriting foundational legal text, changing legal status, manufacturing translations, or promoting a translation merely because a file exists. It restores the approved UI/runtime and integrates current governed content around it.

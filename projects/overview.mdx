EarthCoop has a current project-management surface and a broader economic reference architecture defined by ECON. The **Current product** supports creating projects, assigning a governance scope, submitting them for review, recording review history, and exposing approved project and investment workflows. The **Normative reference architecture** defines how legally valid public-project financing must progress when the complete monetary chain is applied. Some of those end-to-end integrations remain **In development** and must not be inferred merely from a project status such as `approved`.

## Current product lifecycle

The current project service records a project through the following review states:

```text
draft → pending → under_review → approved / rejected / archived
```

| Status | Meaning |
| --- | --- |
| **draft** | The project exists but has not yet been formally submitted for review. |
| **pending** | The project has been submitted and is waiting for review. |
| **under_review** | Formal review has started. |
| **approved** | The review decision is positive. This is a project-status decision, not a monetary transfer. |
| **rejected** | The proposal needs revision or was not approved; eligible projects can be revised and resubmitted. |
| **archived** | The project is no longer active in the normal review/listing flow. |

Review actions are recorded in project history so approval, rejection, revision requests, and later resubmissions are distinguishable events.

## Support is not approval

A project may originate from an individual workflow or from a proposal discussed in a group or public assembly. Where a proposal requires a support threshold, reaching that threshold promotes the matter into the formal review/secretariat workflow. **Support does not approve the project.** It establishes the basis for the next institutional step.

Likewise, **approval is not Transfer**. A positive project decision does not by itself debit members, move money to the project owner, or make funds spendable.

<Warning>
  Do not interpret a support count, an `approved` badge, or a recorded investment intention as proof that Bahar has already moved. Those are separate facts with separate audit events.
</Warning>

## Bahar and Gol

**Bahar** is the monetary unit of EarthCoop. **Gol is the subunit of Bahar**: `1 Bahar = 100 Gol`. Product interfaces or storage layers may display smaller units for precision, but documentation must not describe Gol as a separate currency.

## Public-project reference architecture

For public-project financing, ECON separates legal approval, obligation, monetary state change, and payment. The reference sequence is:

```text
Valid Project Approval
→ Liability Snapshot
→ Commitment
→ Committed Dim
→ conditions met
→ Activation
→ Transfer
→ Active Project Fund
→ execution payments
```

These stages have different meanings:

- **Valid Project Approval** authorizes the project under the applicable governance process; it does not move money.
- **Commitment** records an obligation or reserved amount; Commitment is not Transfer.
- **Committed Dim** remains non-spendable until a lawful Activation condition is satisfied.
- **Activation** changes eligible Dim Bahar into Active Bahar through an authorized route; it is not Creation of new money.
- **Transfer** moves existing Active Bahar between valid economic accounts.
- **Active Project Fund** is the spendable project balance after the required Activation and Transfer have actually occurred.

Only Active Bahar that has actually reached the Active Project Fund is available for project execution payments.

## Investment and project ownership

The current product supports projects owned by a user or a group and includes investment-oriented project fields and workflows. An investment record is an economic/contractual relationship; it must not be treated as a guaranteed return, a governance vote, or automatic ownership of EarthCoop itself.

Project approval also does not guarantee value, profitability, liquidity, insurance coverage, or completion. Those properties depend on the applicable project contract, risk disclosures, insurance arrangement where one exists, and actual execution.

## Current product vs reference architecture

The project review lifecycle and core project/investment surfaces are available in the current product. The complete ECON chain above is the **Normative reference architecture** for compliant monetary execution. Where an advanced step has not yet been connected end to end in the live product, it is **In development** rather than silently assumed to be active.

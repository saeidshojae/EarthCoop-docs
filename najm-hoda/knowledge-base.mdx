EarthCoop maintains knowledge and documentation sources that can support both direct reading and NajmHoda assistance. The available corpus changes over time as documents are added, revised, translated, registered, or removed, so this guide does not freeze the knowledge base to a particular article count or category count.

## What the knowledge sources contain

Depending on the current product configuration, EarthCoop knowledge sources can include product guides, support material, FAQs, policy/reference material, and other indexed content. Different sources can have different authority and lifecycle rules.

A useful distinction is:

- a **product guide** explains how a current feature works;
- a **reference or policy document** describes a governed rule or architecture;
- a **foundational/legal source** has its own registration and legal-effect status;
- a **support answer or blog post** does not automatically have the same authority as a governed source.

NajmHoda should preserve those distinctions rather than flatten every retrieved text into equal authority.

## How NajmHoda may use knowledge

The current NajmHoda architecture includes knowledge-related integration paths. When an orchestration path retrieves relevant sources, those sources can help ground an answer or direct the member to supporting material.

The exact retrieval behavior is implementation-dependent. Indexes, caches, source availability, ranking and ingestion state can change as the subsystem evolves. Documentation therefore should not promise that every chat message uses one fixed keyword algorithm or that a specific number of sources is always retrieved.

<Info>
  A source being present in a repository or knowledge manifest does not by itself prove that every deployed NajmHoda request has already ingested, indexed, or retrieved that source.
</Info>

## Freshness and source-of-truth

Knowledge freshness is not an absolute guarantee. A source can be updated before an index, cache, deployment, or ingestion pipeline has reflected the change everywhere that consumes it.

For important questions, especially about governance, economics, elections, permissions, or legal status, rely on the current authoritative source and its version/status rather than assuming the assistant's first answer is necessarily the newest possible interpretation.

The safe model is:

```text
source update → ingestion/index/cache/deployment → retrievable knowledge
```

Each arrow is an operational step that can have its own timing and validation.

## Translation and version state

EarthCoop documentation can exist in multiple languages and versions. A translated rendition can be current, stale, under review, or not yet translated. Language availability should therefore be read from the document/registry state, not inferred from the existence of one language version.

## When a source and an answer disagree

If a NajmHoda answer appears inconsistent with a current governed document or the live product behavior:

1. check the source's identity, version, and status;
2. check whether the guide describes **Current product**, **In development**, or a normative/reference architecture;
3. prefer the authoritative current source for the governed rule;
4. report the discrepancy so the knowledge or product guide can be corrected.

## Human support

If the available knowledge does not resolve the issue, or the matter requires account-specific investigation, use the formal support workflow. See [Support Tickets](/account/support-tickets).

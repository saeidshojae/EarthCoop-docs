EarthCoop currently exposes controller-backed NajmHoda routes under `/api`. These routes support real application behavior, but the API surface is **evolving / In development** and is **not a stable public external contract** yet. Endpoint presence in the Laravel application should therefore be read as implementation evidence, not as a compatibility promise for third-party clients.

## Verified current capabilities

The current NajmHoda controller contains application paths for authenticated chat, owner-scoped conversation listing and retrieval, conversation archive/delete state changes, feedback, selected support/escalation integration, and page/context-aware orchestration used by first-party EarthCoop flows.

The exact route list, response payload, authentication mode, and client contract can change while the stable API is still being designed.

## Chat boundary

The current chat controller validates a member message, keeps conversation ownership tied to the authenticated user, and routes ordinary non-admin members through the **Steward** mode. An existing conversation can be continued where the current controller accepts its conversation identifier.

This is current application behavior; it is not a guarantee that a future versioned public API will use the same request or response fields.

## Server authorization

Browser/client context is informational. It cannot grant authority to mutate EarthCoop state.

Any action-capable NajmHoda flow requires trusted **server authorization** and the applicable domain checks. The server re-resolves identity, context, ownership, role, and policy before an authorized mutation can occur. Client-supplied actor, role, target, or page fields do not create permission.

<Warning>
  An AI response, suggestion, draft, or apparent confirmation is not proof that the underlying governance, economic, administrative, or support action has been authorized or executed. The responsible domain service must perform and record the action.
</Warning>

## Conversation ownership

Conversation operations are scoped to the authenticated owner. Knowing a conversation ID must not be sufficient to read, archive, or delete another member's conversation.

The current controller includes list, show, archive, and delete-oriented methods. Their exact JSON representation is an implementation detail until a stable client contract is published.

## Escalation and support

NajmHoda has a conditional support-escalation path. Escalation depends on the current policy/service decision and can create or associate support-ticket information where the criteria are met.

Do not interpret the existence of an escalation route as a guarantee that every message, low-confidence answer, or external request can create a support case. Rate limiting, validation, policy, authentication context, and deployment configuration can all matter.

## Draft-capable helpers

Some NajmHoda contexts can prepare drafts or previews. Those helpers do not inherit formal authority from the chat. For example, a secretariat draft helper can prepare or save draft material but is not thereby authorized to submit, register, dispatch, or publish it.

## Authentication

Some NajmHoda routes are protected through the current application's authentication stack. EarthCoop does not yet document a verified general-purpose public token-issuance flow for external clients.

## Stability status

For first-party development, inspect the current route/controller code and tests. For third-party or native clients, wait for the explicitly versioned stable contract.

```text
current Laravel route ≠ stable public API
client context ≠ authority
server authorization + domain execution + audit = valid mutation
```
